A "clear old messages" moderation command worked fine, then started 400ing

A bot command let moderators purge up to 100 messages from a channel using channel.bulkDelete(messages). It worked every time in testing against a busy channel, then started throwing a 400 the first time someone ran it against a quieter channel where the oldest selected messages had been sitting untouched for a while.

Why: bulk delete silently refuses to touch anything past 14 days old

Discord's bulk-delete endpoint is explicitly scoped to recent messages — anything older than two weeks has to be deleted one at a time through the regular single-message delete endpoint instead. discord.js's bulkDelete() has a filterOld option that silently drops the too-old messages from the batch rather than erroring, but only if it's passed explicitly; calling it with a raw array of fetched messages and no second argument hits the API's hard rejection the moment even one message in the batch is too old. 

// Throws a 400 if any message in the collection is >14 days old
const messages = await channel.messages.fetch({ limit: 100 });
await channel.bulkDelete(messages);

// Drops the too-old ones from the batch instead of erroring
await channel.bulkDelete(messages, true); // filterOld = true

// Anything that still needs deleting goes one by one
const tooOld = messages.filter((m) => Date.now() - m.createdTimestamp > 14 * 24 * 60 * 60 * 1000);
for (const msg of tooOld.values()) {
  await msg.delete();
}

The actual lesson

A "delete these messages" bulk command needs a fallback path for old messages from day one, not just a happy path for recent ones — either pass filterOld and accept that some messages silently won't be removed, or split the batch up front and fall back to single deletes (which are also individually rate-limited, so that path is much slower for a large purge).
