A client asked why every button got an ugly blue ring on tap

A custom button component had outline: none removed in favor of a nicer focus style written against :focus. It looked right on desktop. On the client's phone, every single tap on every button lit up the same ring — not just the one being navigated to with a keyboard, which was the only case the design was meant for.

Why: :focus matches on any focus, mouse or touch included

:focus doesn't know or care how the element became focused — clicking, tapping, or tabbing to it all match the same selector. The old "remove the ugly default ring" fix of *:focus { outline: none } plus a custom style run into exactly this: the custom ring now fires on every pointer interaction too, which is the visual noise keyboard-only focus rings were trying to avoid in the first place. :focus-visible matches the browser's own heuristic for "the user probably wants to see where focus is" — keyboard navigation, programmatic .focus() in some cases — and skips it for a plain mouse or touch click on most elements. 

/* Fires on every click/tap too — not what was wanted */
button:focus {
  outline: 2px solid var(--accent);
}

/* Only the browser's own "this was probably a keyboard/AT user" cases */
button:focus-visible {
  outline: 2px solid var(--accent);
}
button:focus:not(:focus-visible) {
  outline: none; /* mouse/touch focus gets no ring at all */
}

The actual lesson

Never blanket-disable the focus ring with outline: none on :focus alone — that silently breaks keyboard navigation for every visitor who tabs through the page. :focus-visible is the selector that actually encodes "show a ring only when it's useful", and pairing it with :focus:not(:focus-visible) covers the "hide it otherwise" half without removing focus indication altogether.
