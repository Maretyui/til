Tick times crept up on a server with nobody building anything new

A survival server's average tick time had been quietly climbing for weeks, with no obvious cause — the player count hadn't grown and no new redstone contraptions had been reported. A tick profiler pointed at one chunk doing far more work than it should for an area nobody was standing in.

Why: forceloaded chunks ignore distance to players entirely

/forceload add <x1> <z1> [x2] [z2] was run months earlier to keep an automatic farm running while everyone was offline overnight. Normal chunks only tick — mob AI, random ticks, redstone, crop growth — while a player is within simulation distance. A forceloaded chunk ticks forever, with zero players anywhere near it, until something explicitly removes the flag: 

/forceload add 220 480 260 520   # keeps that whole area ticking indefinitely
/forceload list                  # easy to forget this was ever run
/forceload remove 220 480 260 520

Server restarts don't clear it either — forceload.json in the world save persists the list across reboots by design, so the farm kept grinding (and costing tick time) through every restart in between.

The actual lesson

/forceload has no built-in expiry and no in-game reminder that it's active, so it's easy to add for a one-off reason and never remove. Run /forceload list as a routine part of investigating tick lag before looking anywhere else, and treat any /forceload add as something that needs a matching /forceload remove once the reason for it is gone — not a "set and forget" toggle.
