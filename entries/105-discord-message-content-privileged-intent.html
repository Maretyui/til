A keyword-triggered bot command worked locally and then did nothing after deploy

A bot feature watched for plain messages containing a certain keyword (no slash command, just regular chat) and reacted to them. It worked immediately in local testing against a dev server, then went completely silent after the bot was invited to a different server — no errors, no crashes, the message handler just never matched anything, because message.content was arriving as an empty string on every message.

Why: MESSAGE_CONTENT is a privileged intent with two separate switches

Reading the text of messages the bot didn't author requires the MessageContent gateway intent, and that intent is privileged — declaring it in code (GatewayIntentBits.MessageContent) is only half of what's needed. It also has to be toggled on for the application in the Discord Developer Portal, under Bot → Privileged Gateway Intents. Skip the portal switch and the gateway doesn't reject the connection or throw — it just silently strips content down to an empty string on every message event, which is exactly indistinguishable from "the keyword genuinely isn't in this message" unless you already know to suspect it. 

const client = new Client({
  intents: [
    GatewayIntentBits.Guilds,
    GatewayIntentBits.GuildMessages,
    // Also toggle "Message Content Intent" on in the Developer Portal
    // under this application's Bot settings - this line alone is not
    // enough, and nothing here will warn you if you forget the portal step
    GatewayIntentBits.MessageContent,
  ],
});

It stayed invisible locally because the dev server's bot application already had the portal toggle flipped on from an earlier project; a second bot application created for testing a different server started from the toggle's actual default (off), which is where the empty-string behavior showed up.

The actual lesson

Any gateway intent flagged "privileged" (message content, presence, and the guild members intent) needs the matching portal toggle checked on a per-application basis, separately from whatever's declared in code — and because verified bots in 100+ servers need Discord's approval to keep a privileged intent at all, that portal setting is worth confirming first whenever a content-reading feature "does nothing" with no error anywhere in the logs.
