A "resize" handler ran twice on page load before the user touched anything

A sidebar widget measured its own width with ResizeObserver and re-rendered a chart whenever that width changed, to avoid the classic window.resize problem of firing for every unrelated layout change on the page. The chart library logged a full re-render the instant the observer was attached — before the element had resized, been scrolled into view, or done anything at all.

Why: the spec defines the first callback as unconditional

ResizeObserver doesn't wait for an actual size change before calling the callback the first time. Per spec, calling observe() queues a resize observation that fires on the very next frame regardless of whether the size changed — effectively treating "I just started watching this element" as a resize event in itself. Every later call really does mean the size changed; only that first one is unconditional. 

const ro = new ResizeObserver((entries) => {
  // This runs once immediately after observe(), with no resize
  // having happened yet, and then again on every real resize after.
  renderChart(entries[0].contentRect.width);
});
ro.observe(sidebar);

The actual lesson

Code that assumes the callback only means "this element's size changed" will double-run its initial setup — harmless for a pure re-render like the chart above, but a real bug if that callback also does something with side effects (posting a resize event upstream, incrementing a counter, firing an analytics beacon). If the initial call matters, track whether it's the first entry for that observed element and branch on it; don't assume observe() is a silent no-op until something actually moves.
