PowerShell's Out-File -Encoding utf8 silently adds a BOM

I had a small PowerShell helper script that wrote a JSON config file for a Go service to read on startup. It looked completely reasonable: 

$json | Out-File -Encoding utf8 -FilePath config.json

The file opened fine in a text editor, the JSON was valid by eye, and yet the Go service refused to parse it, failing on byte zero of an otherwise well-formed file. No amount of re-checking the JSON syntax explained it, because the problem wasn't the JSON — it was three invisible bytes in front of it.

The cause

PowerShell's -Encoding utf8 is not plain UTF-8. It's UTF-8 with a byte-order mark (EF BB BF) prepended, a legacy default that predates UTF-8 becoming the de facto standard without a BOM. Most strict JSON parsers (including Go's encoding/json) treat those leading bytes as invalid input rather than silently skipping them, since a BOM isn't valid JSON.

The fix

Skip Out-File/Set-Content for anything that has to be read by a strict parser, and write the bytes directly instead: 

[System.IO.File]::WriteAllText("config.json", $json)

WriteAllText defaults to BOM-less UTF-8, which is what every non-Windows-native tool actually expects. Worth checking for any script that hands a generated JSON/YAML/.env file to something outside the Windows/.NET world — the file will look correct in every editor and still fail to parse.
