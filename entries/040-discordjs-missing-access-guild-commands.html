discord.js guild command registration 403s if the bot isn't in the guild yet

Spinning up a new ticket bot deployment for a fresh Discord server, the very first REST.put() call to register guild slash commands against the new guild ID came back with DiscordAPIError[50001]: Missing Access. The bot token was correct, the application ID was correct, and the exact same registration code worked fine against every other guild the bot already had commands in.

The bot has to actually be a member of the guild first

A bot token authenticates the *application*, but registering commands scoped to a specific guild (as opposed to global commands) still requires the bot to already be present as a member of that guild — the API has no way to attach guild-scoped commands to a server the bot hasn't joined. Copying a guild ID out of Discord's UI and wiring it into config isn't enough on its own; the invite step has to happen first, and it's easy to skip when a config-only deployment feels "done" before anyone's actually clicked the invite link. 

// looks like a permissions/token bug, but it's really an ordering bug:
await rest.put(
  Routes.applicationGuildCommands(clientId, guildId),
  { body: commands },
); // -> DiscordAPIError[50001]: Missing Access

// fix: invite the bot to that guild first, with the scopes it needs
// https://discord.com/oauth2/authorize?client_id=CLIENT_ID&permissions=8&scope=bot%20applications.commands

The actual lesson

When a fresh guild-scoped deployment throws "Missing Access" on its very first registration call, check guild membership before touching token/permission config — open the server's member list and confirm the bot is actually listed there. If it isn't, the fix is just clicking the OAuth invite URL with the bot and applications.commands scopes, not debugging the registration code itself.
