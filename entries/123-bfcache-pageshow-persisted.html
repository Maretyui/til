A "connecting..." status kept showing after navigating back, even though the connection was fine

A page opened a WebSocket on load and showed a status badge while it connected. Users who navigated away and then hit the browser's Back button sometimes landed on a page permanently stuck on "connecting...", even though the socket underneath was open and working — clicking anything that depended on the connection just did nothing.

Why: the page was never reloaded, so the "on load" code never ran again

Modern browsers can restore an entire page — DOM, JS heap, in-flight timers — from an in-memory snapshot on back/forward navigation, instead of reloading it. This is the back/forward cache (bfcache). When that happens, DOMContentLoaded and the page's other "on load" listeners do not fire again, because the page was never torn down in the first place. The status badge was only ever updated by the connection-setup code that ran on the original load, so a bfcache-restored page kept showing whatever state it was in at the moment it got frozen — in this case, "connecting...", because the snapshot happened to be taken before the socket's open event fired. 

// Runs once per real page load. Never runs again on a bfcache restore,
// so any UI state set here goes stale the moment the page is frozen.
window.addEventListener('DOMContentLoaded', () => {
  connectSocket();
  setStatus('connecting...');
});

// Fires on every navigation that lands on this page, including a
// bfcache restore. event.persisted tells you which kind just happened.
window.addEventListener('pageshow', (event) => {
  if (event.persisted) {
    reconcileConnectionState();
  }
});

The actual lesson

Anything that sets UI state based on an async result — a connection status, a "last updated" timestamp, a fetched feature flag — needs a pageshow listener that checks event.persisted and re-syncs, not just a one-time setup on load. The same applies in reverse for cleanup: a pagehide listener (not beforeunload, which can itself block the page from being eligible for bfcache) is the right place to pause timers or mark connections as "may be stale" before the page is frozen.
