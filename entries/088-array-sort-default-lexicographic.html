A "sort by price, low to high" list put 100 before 20

A product list had a sort-by-price feature: prices.sort() on an array of plain numbers. It looked right for small test data (single-digit prices), then shipped and immediately looked broken — [20, 100, 3] came back as [100, 20, 3] instead of [3, 20, 100].

Why: the default comparator converts everything to strings first

Array.prototype.sort() with no comparator function doesn't sort numerically at all — it converts every element to a string and sorts those in UTF-16 code-unit order. Comparing "100" and "20" as strings looks at the first character first: "1" sorts before "2", so 100 ends up before 20 regardless of which number is actually larger. 

[20, 100, 3].sort();
// => [100, 20, 3]  — sorted as the strings "100", "20", "3"

[20, 100, 3].sort((a, b) => a - b);
// => [3, 20, 100]  — sorted numerically, as intended

The actual lesson

sort() always needs an explicit comparator for numbers — (a, b) => a - b for ascending, (a, b) => b - a for descending. This isn't a version-specific quirk or something that changed; it's been the documented default behavior since the array sort spec was first written, which is exactly why it's easy to miss until a dataset happens to include a number with more digits than the rest.
