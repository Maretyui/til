A form field's border needed to turn red, but only after a sibling failed validation

A small contact form grouped a label and input inside a <div class="field"> wrapper, and the ask was simple: give the wrapper a red border once its input became invalid, so the whole field (label included) reads as errored, not just the input's own default browser outline. The obvious- looking .field:invalid doesn't work — :invalid matches the input itself, and the wrapper div is never invalid, only its child is.

Why: CSS had no way to select a parent based on its children

Every CSS selector before :has() selects downward — an ancestor, a following sibling, a direct child — never a parent based on what's nested inside it. That direction always needed JavaScript: listen for an invalid event on the input, then toggle a class on the wrapper by hand. :has() (the "relational pseudo-class," landed in every major engine by 2023) fixes exactly this gap — it matches an element if any selector passed to it matches something inside that element. 

.field:has(:invalid) {
  border: 1px solid crimson;
}

/* also works for "does this card contain an image at all" */
.card:has(img) {
  grid-template-columns: 120px 1fr;
}

/* or styling a label differently when its own input is focused,
   without needing a wrapping :focus-within on the label itself */
label:has(input:focus) {
  color: var(--accent);
}

The actual lesson

Any "if this container has an X inside it, style the container differently" rule that used to need a JS event listener and a manually toggled class can now often be written as a single :has() rule instead — worth checking before reaching for JavaScript the next time the styling logic is really about a parent reacting to its own contents.
