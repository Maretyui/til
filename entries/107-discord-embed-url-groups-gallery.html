A bot sent four image embeds in one message and Discord rendered four separate cards

A command replied with several screenshots by building one embed per image and sending them all in a single message's embeds array (Discord allows up to 10 per message). The expectation, based on how image galleries look everywhere else in the client, was a single 2x2 grid. Instead every embed rendered as its own full-width card stacked vertically, each with its own border, which looked broken for anything past two images.

Why: the grid is keyed on embed.url, not on the message

Discord only merges sibling embeds into one gallery block when they all have the same top-level url field. The image itself can point anywhere; it's the embed's url — normally only meaningful for making the title clickable — that acts as the grouping key the client checks first. Leave it unset, or set it differently per embed, and each one is treated as an unrelated card and laid out separately. 

const gallery = screenshots.map((imageUrl) => ({
  url: 'https://example.com/report/42', // same on every embed in the group
  image: { url: imageUrl },
}));

await channel.send({ embeds: gallery });

Any stable string works as the shared url — it doesn't need to resolve to a real page, and most bots just reuse the command's own result-page link or a dummy https:// placeholder. The only requirement is that every embed destined for the same gallery carries the identical value.

The actual lesson

"Multiple image embeds in one message" and "an image gallery" are not automatically the same thing client-side — grouping is an opt-in keyed on a field that has nothing to do with images, so a gallery that silently degrades into a stack of cards is usually a missing or mismatched url, not a client rendering bug.
