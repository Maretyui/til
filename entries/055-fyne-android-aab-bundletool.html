-release mode built successfully, but there was no .apk anywhere

Cross-compiling a Fyne desktop app for Android with fyne-cross in -release mode (needed for a real signed build targeting a modern SDK, rather than the debug path's hardcoded old targetSdkVersion) finished without errors. But the output directory only contained a single .aab file — trying adb install on it failed immediately with a generic "not a valid APK file" error.

An .aab is a publishing format, not an installable one

An Android App Bundle packages the app as a set of per-device "split" modules (different ABIs, screen densities, languages) that only the Google Play Store's own delivery pipeline knows how to assemble into a device-specific APK at install time. It was never meant to be installed directly — -release mode switched the output format to the Play Store's expected shape, and sideloading just isn't part of that flow at all.

The fix: bundletool builds a universal APK from the bundle

The fyne-cross Android image already ships bundletool at /usr/local/bin/bundletool. It can turn the same signed .aab back into a normal, sideloadable APK: 

bundletool build-apks \
  --bundle=app.aab \
  --output=app.apks \
  --mode=universal \
  --ks=release.keystore \
  --ks-pass=pass:KEYSTORE_PASSWORD \
  --ks-key-alias=myalias \
  --key-pass=pass:KEY_PASSWORD

# .apks is itself just a zip — pull the real APK out of it
unzip app.apks -d app-apks && cp app-apks/universal.apk ./app.apk

The actual lesson

-release mode isn't just "the more correct debug build" — it changes what kind of artifact comes out entirely. Sideloading a release build needs one extra conversion step that the debug path never required, since debug mode always produced a plain APK to begin with.
