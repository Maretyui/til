A server logo baked into a resource pack's tab-list header never showed up

A Minecraft server used a bitmap font provider in its resource pack to swap one rarely-used Unicode character for a small logo image, so a plugin could drop that character into the tab-list header and have players see a graphic instead of text. The pack loaded without any error, and the character rendered fine as blank space — but the logo itself never appeared, on any client, for weeks.

Why: the source image was way bigger than a font atlas page

Minecraft's font system packs bitmap glyphs into atlas textures in 256×256 pixel pages. A provider image with any dimension larger than that doesn't get scaled down or tiled — it's simply skipped, with nothing written to the log. The source logo here was 1672×941, more than six atlas pages wide, so it silently failed to load while the rest of the pack (including the font entry's fallback blank glyph) kept working normally. 

{
  "providers": [
    {
      "type": "bitmap",
      "file": "custom:logo.png",
      "ascent": 31,
      "height": 56,
      "chars": ["㍿"]
    }
  ]
}
// logo.png itself must be at most 256x256 — the "height" field only
// controls the rendered line-height, not the source resolution

The actual lesson

Resize the source texture down to fit within one 256×256 atlas page first, independent of how large it should visually render — the height/ ascent fields in the provider entry only scale and vertically position the glyph within a line of text, they don't relax the hard size cap on the underlying image. A pack that loads with zero errors is not the same as a pack whose every provider actually got applied — worth a visual check in-game after any font-provider change, not just a pack-format validation pass.
