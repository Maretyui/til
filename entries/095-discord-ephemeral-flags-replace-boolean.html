A working ephemeral reply started printing a deprecation warning

A slash command handler replied with interaction.reply({ content, ephemeral: true }) to keep a status message visible only to the user who ran it. It still worked, but a recent discord.js upgrade started logging a deprecation warning on every single call, which was easy to miss buried between normal request logs.

Why: ephemeral is now a bit flag, not a boolean option

Discord's own API moved ephemeral-ness (and several other reply behaviors, like suppressing embeds) into a generic flags bitfield on the message payload instead of one-off boolean fields. discord.js followed suit: the ephemeral shorthand still works for backward compatibility, but it's marked deprecated in favor of setting MessageFlags.Ephemeral directly. 

// deprecated, still functions but warns
await interaction.reply({ content: 'Done.', ephemeral: true });

// current form
const { MessageFlags } = require('discord.js');
await interaction.reply({
    content: 'Done.',
    flags: MessageFlags.Ephemeral,
});

// flags are combinable, e.g. ephemeral + no link embeds
await interaction.reply({
    content: 'https://example.com',
    flags: MessageFlags.Ephemeral | MessageFlags.SuppressEmbeds,
});

The gotcha: flags and ephemeral can't both be passed in the same call - discord.js throws if it sees both, so a mechanical find-and-replace across a codebase needs to actually remove the old key, not just add the new one alongside it.

The actual lesson

When a wrapper library's "just pass a boolean" shorthand gets deprecated in favor of a bitfield, it's usually because the underlying API grew more flags that boolean couldn't represent cleanly. Worth switching early, since the shorthand tends to get removed entirely in a later major version rather than staying around forever.
