Discord Components V2 messages can't carry a top-level content field

Rebuilding a ticket bot's panel/ticket cards with Discord's newer Components V2 message flag (full-width layout components instead of classic embeds) meant swapping every reply()/ send() call over to a components array with the IsComponentsV2 message flag set. One thing broke immediately: pinging the ticket creator or the staff role when a new ticket opened.

The problem

A classic embed-based message can set both content (for the ping/mention text) and embeds in the same call — Discord renders the plain-text content above the embed. Components V2 messages don't work that way: once the IsComponentsV2 flag is set, Discord silently ignores (or in some client versions, rejects) a top-level content field entirely. The mention text just never shows up, with no error surfaced — the message sends fine, it's just missing the ping.

The fix

Send the mention as its own ordinary plain-text message first, then send the Components V2 card as a separate message right after it: 

await channel.send({ content: `<@${userId}> <@&${staffRoleId}>` });
await channel.send({
  flags: MessageFlags.IsComponentsV2,
  components: [ticketCard],
});

Two messages instead of one, but it's the only reliable way to get both a real ping notification and the full-width card layout in the same flow.

The actual lesson

Components V2 isn't just "embeds with new layout blocks" — it's a genuinely different message shape with its own constraints. Anything that assumed the classic content + embeds combo (pings, plain-text prefixes, anything outside the component tree) needs to move to a separate message instead of silently breaking.
