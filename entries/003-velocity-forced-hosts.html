Velocity's forced-hosts routes multiple domains to one Minecraft server

I run a couple of small Minecraft servers behind a single Velocity proxy, and both domains pointed at the same public IP. The naive expectation was that players would need to type /server <name> after connecting, since there's only one entry point on port 25565 regardless of which hostname they used to get there.

The fix

Velocity reads the hostname the client actually connected with (the same SNI-like info Minecraft's handshake packet sends) and can map it straight to a backend server, no manual switching needed: 

[forced-hosts]
"survival.example.com" = ["survival"]
"creative.example.com" = ["creative"]

With that in place, a player typing either domain lands directly on the matching backend server. Both hostnames can share the exact same IP and port — Velocity does the routing entirely at the application layer, similar in spirit to how a reverse proxy like nginx picks a backend by Host header.

Gotcha

A leftover inline forced-hosts = {} line earlier in the same TOML file conflicts with a later [forced-hosts] table — it's a duplicate key, and Velocity fails to parse the config at all rather than just ignoring the empty one. Worth grepping for the inline form before adding the table version to an existing config.
