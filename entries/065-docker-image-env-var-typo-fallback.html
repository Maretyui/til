A web UI in front of a REST API started failing auth out of nowhere

A small Docker Compose stack had a backend container exposing a REST API, and a separate web-UI container that talked to it using basic auth. Both containers had been running fine for months. Then, after rotating the backend's admin password, the web UI broke completely — every page showed a generic "authorization failed" error, and on top of that the browser kept re-prompting for the site's own unrelated HTTP basic-auth credentials, which made the first few minutes of debugging chase the wrong layer entirely.

Why: three env vars in the compose file didn't match what the image actually reads

The web UI's compose service set API_AUTH_URL, API_AUTH_USER, and API_AUTH_PASSWORD. The application inside the image, though, reads AUTH_URL, AUTH_USER, and AUTH_PASSWORD — no API_ prefix. Since none of the set variables matched, the app silently fell back to its own hardcoded defaults, which happened to already be correct for months by pure coincidence (the default user/URL matched, and the default password was — until that day — also the real one). The mismatch was invisible until the real password actually changed and the stale fallback stopped being right. 

# set, but never read by the app — three extra characters, silently ignored
API_AUTH_URL=http://backend:8080
API_AUTH_USER=admin
API_AUTH_PASSWORD=changeme

# what the image's own settings loader actually looks for
AUTH_URL=http://backend:8080
AUTH_USER=admin
AUTH_PASSWORD=changeme

The actual lesson

When a value seems to load correctly for a long time, that isn't proof the wiring is right — it can just mean the code's own fallback happens to agree with the intended value for now. The way to tell them apart is to inspect what the running process actually loaded (e.g. dump the resolved setting from inside the container) rather than only checking what's set in the compose file or the environment. A value that's correct by coincidence looks identical to one that's correctly wired, right up until the coincidence ends.
