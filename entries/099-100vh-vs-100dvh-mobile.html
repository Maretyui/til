A full-height hero section left a gap at the bottom on phones

A height: 100vh hero section looked right in a desktop browser and in Chrome DevTools' device emulation, but on an actual phone, loading the page left a strip of the page background visible below the hero, as if it were a few dozen pixels short.

Why: 100vh is the largest possible viewport, not the current one

Mobile Safari and Chrome show and hide their own address bar/toolbar chrome as the page scrolls. 100vh is defined against the largest viewport size — the one with the browser UI collapsed — so right after a fresh page load, while the address bar is still fully visible, the actual visible area is shorter than 100vh says it is. The element isn't too short; the viewport it's measured against is temporarily taller than what's on screen. 

/* Sized against the collapsed-chrome viewport - taller than
   what's actually visible right after a fresh page load */
.hero { height: 100vh; }

/* Sized against whatever viewport height is true right now,
   chrome included */
.hero { height: 100dvh; }

The actual lesson

dvh (dynamic viewport height) tracks the browser chrome's current state instead of assuming the smallest or largest case; lvh/svh exist too for when the largest/smallest extremes are specifically wanted. For anything meant to fill "the screen" on mobile, 100dvh is the one that actually matches what the user sees at any given moment, with 100vh kept only as a fallback for the handful of older browsers that don't support the newer units yet.
