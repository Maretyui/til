Tailwind v4's spacing scale accepts decimals like w-4.5 with no bracket syntax needed

Doing a pass over a portfolio site's contact section, I spotted className="w-4.5 h-4.5" on an icon and className="w-4.3 h-4.3" on another, right next to normal integer classes like text-3xl. My first read was "typo — someone meant w-5 or forgot the bracket syntax for an arbitrary value", so I went to fix it.

They weren't typos

In Tailwind v3, a non-integer utility like that genuinely wouldn't exist — you'd need the arbitrary-value escape hatch, w-[1.125rem]. Tailwind v4 changed how the whole spacing scale works: instead of a fixed lookup table of named sizes, most spacing-based utilities are generated from one CSS variable and a multiplier: 

/* v4's default spacing scale, roughly */
--spacing: 0.25rem;
.w-4  { width: calc(var(--spacing) * 4); }   /* 1rem   */
.w-4\.5 { width: calc(var(--spacing) * 4.5); } /* 1.125rem */

Because it's a calc() multiplication rather than a lookup table, any numeric value — including decimals — just works, with no bracket syntax and no config changes. w-4.5 and h-4.3 compile to real, valid classes.

Why this almost bit me

I'd nearly "fixed" perfectly valid, intentional sizing based on a v3-era assumption baked into muscle memory. The one thing worth checking before treating a fractional Tailwind class as a mistake: 

grep tailwindcss package.json
# "tailwindcss": "^4.x" → decimals on spacing utilities are real classes,
# not arbitrary-value shorthand and not typos.
