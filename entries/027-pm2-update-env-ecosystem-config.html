pm2 restart --update-env doesn't always re-read ecosystem.config.js

A backend API's DATABASE_URL pointed at a stale LAN IP inside ecosystem.config.js's env block — fixed on disk, then deployed the usual way: 

pm2 restart api-name --update-env

That flag exists specifically to force PM2 to re-capture the environment instead of reusing whatever it snapshotted at the first pm2 start — the known fix for the more common version of this problem. It didn't work here. Every authenticated request still hung for minutes against the old IP, even though unauthenticated requests and raw queries straight against the database both looked completely healthy — which is what made this take so long to pin down: the fast-failing, easy-to-check paths weren't the ones that were actually broken.

--update-env refreshes PM2's env, not the config file behind it

--update-env tells PM2 to re-read the environment it already has associated with that process entry — it does not re-parse ecosystem.config.js and re-derive a new env block from it. If the process was originally started from that file, PM2's internal process metadata can still be carrying values from whenever it was first started, and a name/id-based restart — flagged or not — reapplies that cached metadata rather than the file's current contents.

The actual fix

Delete the process entry and start it fresh directly from the config file, so PM2 has no choice but to build its metadata from what's on disk right now: 

pm2 delete api-name
pm2 start ecosystem.config.js
pm2 save

Verified with a real signed, authenticated request end-to-end (44ms, not two minutes) before considering it fixed.

The actual lesson

For any app managed via an ecosystem.config.js, don't trust pm2 restart — flagged with --update-env or not — to pick up a config file change. Only pm2 delete followed by pm2 start ecosystem.config.js reliably rebuilds the process from what's actually on disk. And when debugging something that "sometimes" fails, prefer testing the real, fully authenticated code path over adjacent-looking fast checks — they can pass for entirely unrelated reasons and send you down the wrong trail for hours.
