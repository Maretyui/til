Discord interactions expire in 3 seconds, defer before slow calls

A Discord ticket bot's priority/close/reopen buttons started failing intermittently in production with a generic error, but only on channels that had just been renamed. The handler did a channel rename, then a couple of permission checks, then finally called interaction.reply(): 

async function onPriorityChange(interaction, channel) {
  await checkPermissions(interaction);
  await channel.setName(`🔴-${channel.name}`);
  await interaction.reply({ content: 'Priority updated.' });
}

Discord gives a bot exactly 3 seconds to acknowledge an interaction (a button click, slash command, etc.) before it expires and any reply attempt fails with a 404 / "Unknown interaction" (error code 10062).

The cause

Channel renames are rate-limited to roughly 2 per 10 minutes per channel. If a channel had already been renamed recently, the Discord REST client silently queues the next rename request and waits out the rate limit — which can easily blow past 3 seconds. By the time channel.setName() resolves, the interaction token is already dead, and the final interaction.reply() 404s.

The fix

Acknowledge the interaction immediately, before any slow API call, then edit that acknowledgement once the real work is done: 

async function onPriorityChange(interaction, channel) {
  await checkPermissions(interaction);
  await interaction.deferReply();
  await channel.setName(`🔴-${channel.name}`);
  await interaction.editReply({ content: 'Priority updated.' });
}

deferReply() shows a "thinking..." state and buys up to 15 minutes to send the real response via editReply(). As a rule of thumb: call deferReply() as the very first thing in any handler that touches the Discord API more than once before responding — cheap handlers that reply immediately don't need it, but anything doing a rename, a fetch, or a DB round-trip first should defer on principle rather than hoping it stays under 3 seconds.
