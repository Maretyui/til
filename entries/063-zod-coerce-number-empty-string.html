An optional number field was silently defaulting to zero

A form had a genuinely optional numeric field — leave it blank and it should just stay unset in the database. The API route validated the request body with a Zod schema using z.coerce.number().optional(). Leaving the field empty in the form worked fine in casual testing... except every row that skipped the field ended up with a real 0 stored, not null. Nobody had entered a zero on purpose.

Why: an empty form field arrives as an empty string, and Number("") is 0

HTML forms always submit text. A field left blank doesn't arrive as undefined — it arrives as the empty string "". z.coerce.number() coerces by running the input through JavaScript's own Number(), and Number("") evaluates to 0, not NaN and not undefined. So the value passes validation cleanly as a normal, intentional zero, and `.optional()` never even gets a chance to apply — the field was never actually undefined by the time Zod's optional check ran. 

// silently turns a blank field into 0:
const schema = z.object({
  heightCm: z.coerce.number().optional(),
});

// fixed: normalize "" to undefined before coercion runs
const schema = z.object({
  heightCm: z.preprocess(
    (val) => (val === "" ? undefined : val),
    z.coerce.number().optional()
  ),
});

The actual lesson

Any optional numeric field fed by an HTML form needs an explicit empty-string-to-undefined step before z.coerce.number() ever sees it — the coercion itself won't do it for you, and the resulting bad value (a real, valid-looking 0) won't throw anywhere, it'll just sit quietly in the data. Worth double-checking every optional numeric field in a schema for this exact pattern, not just the one that got caught.
