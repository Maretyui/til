A rebuilt plugin just wasn't there anymore

After bumping a Paper plugin's build against a newer server jar, the freshly built .jar dropped into plugins/ and the server restarted clean — no stack trace, no error line in the console at all. The plugin's commands just didn't exist, as if the file had never been copied over. Diffing the console output against a previous good start showed the plugin's own startup banner missing entirely, which was the first real clue: it hadn't crashed during onEnable(), it had never been loaded in the first place.

Why: api-version is a hard gate before any of your code runs

plugin.yml's api-version field isn't a hint or a compatibility note — Paper checks it before touching the plugin's actual classes, and if the declared version is newer than what the running server implements, it silently skips loading the plugin instead of throwing anything. The build had been updated to target a newer API package for an unrelated reason, which bumped the generated api-version along with it, while the actual server jar running in production was still one minor version behind. Nothing about the plugin's code was wrong; the version gate rejected it before onLoad() ever ran. 

# plugin.yml
name: ExamplePlugin
main: com.example.ExamplePlugin
version: 1.4.0
api-version: '1.21'   # must be <= the running server's own API version

# the server log for a silently skipped plugin looks completely
# unremarkable - no warning, just an absence:
[Server] Loading plugins...
[Server] Done (4.821s)! For help, type "help"
# (no "[ExamplePlugin] Enabling ExamplePlugin v1.4.0" line anywhere above)

The actual lesson

Treat api-version as a floor for the server, not a moving target that follows the build environment automatically — pin it explicitly to the oldest API the plugin actually needs rather than whatever the local dev server jar happens to be, and when a plugin goes quiet with zero errors after a rebuild, check for a missing enable banner in the log before assuming the jar failed to copy or a dependency was missing.
