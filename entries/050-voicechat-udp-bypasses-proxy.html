Voice chat worked on one backend server and not another, same proxy setup

Running several Paper servers behind a Velocity proxy (players connect once to the proxy's port, Velocity routes them to whichever backend they're on) is the normal setup for regular play traffic. Adding the Simple Voice Chat mod, the expectation was that voice would just ride along the same way — one exposed port, Velocity sorting out where it goes. It didn't: voice worked for players on the backend whose own port happened to be open directly, and silently failed for everyone else.

Why: voice chat is a separate UDP stream, not a Minecraft protocol packet

Velocity's routing only understands the actual Minecraft protocol — the TCP connection players make on the proxy's own port. Simple Voice Chat doesn't send audio over that connection at all; each backend server opens and advertises its own UDP port for voice, and the client connects to that port directly once it learns which one to use. There's no proxy hop involved for voice at all, so whatever normally makes multi-backend routing transparent for chat and movement does nothing here. 

# TCP: player -> proxy:25565 -> Velocity picks the backend
# UDP (voice chat): player -> backend's own advertised port, direct,
# no proxy involved regardless of which backend that is

The fix

Forward the whole voice chat UDP port range straight to the game server host at the router/firewall level, separately from the single TCP port already forwarded for Velocity — and keep every backend's TCP port itself firewalled off from the outside world, since those still bypass the proxy's auth forwarding if reachable directly.

The actual lesson

"It's behind the proxy" is a per-protocol claim, not a per-server one. A mod or plugin that opens its own socket instead of piggy­backing on the game's existing connection needs its own explicit path through the network, even in a setup where everything else already routes cleanly through one shared entry point.
