Sharing a Next.js site's link in Discord showed no preview image

A small marketing site had a normal-looking openGraph block in its root layout.tsx — title, description, a relative images path pointing at a file in public/. Locally everything rendered fine. In production, pasting the URL into Discord/Slack/iMessage produced a link preview with no image at all.

Why: a relative OG image URL needs something to resolve it against

Open Graph tags are read by an external crawler, not a browser that already knows the current origin — a relative images: ["/og-image.png"] has to become an absolute URL somewhere. Next.js's Metadata API does this resolution automatically, but only if it's told the site's real base URL via metadataBase. Without it, Next.js silently falls back to resolving against http://localhost:3000 and logs a one-line warning in the server console that's easy to miss in a full build log. 

// app/layout.tsx
export const metadata: Metadata = {
  metadataBase: new URL("https://example.com"), // the missing piece
  title: "Example",
  openGraph: {
    images: [{ url: "/og-image.png", width: 1200, height: 630 }],
  },
};

The actual lesson

Any Next.js App Router project using relative image paths anywhere in its Metadata (openGraph, twitter, icons) needs metadataBase set to the real production origin, or every crawler that isn't running against localhost resolves those paths to a dead link. Worth grepping a project's layout.tsx for openGraph/twitter blocks and confirming metadataBase is actually present whenever a new relative image path gets added.
