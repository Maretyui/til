a root-owned log file can make every later error look inexplicably generic

I was debugging a fresh install by SSHing in as root and running a handful of admin CLI commands directly — the kind of thing that normally runs under a dedicated service user (www-data, in this case) via the web server, but felt harmless to run manually once or twice while poking around. 

ssh root@host
cd /var/www/app && php artisan some:command

One of those commands happened to be the first thing that day to touch the app's log file, so the framework created it fresh — owned by root:root, since that's who ran the process. Nothing about the command itself failed or printed a warning.

Where it actually bit

Later, a real request came in through php-fpm, running as www-data as always, and hit an unrelated bug. The framework's own exception handler tried to do its normal job — write the exception to that day's log file — and couldn't, because www-data has no write permission on a file owned by root:root. The handler's attempt to log the *original* exception then itself threw, and what actually reached the HTTP response was a second, unrelated, near-content-free error (something like a bare UnexpectedValueException with no message) instead of anything describing the real problem.

From the outside this looked like the framework had started failing for no reason, on every request, with an error too vague to act on — when the actual root cause was a permissions mismatch on a log file from an unrelated command run hours earlier.

The fix, and the habit

ls -la storage/logs/
chown www-data:www-data storage/logs/laravel-*.log

Fixing the ownership immediately surfaced the real, original error on the next request. The lasting habit: if an app's errors ever start looking suspiciously generic or content-free right after some manual maintenance, check log file ownership before doing anything else — and prefer sudo -u www-data php artisan ... over a bare root shell for one-off admin commands, so the log file (if one gets created) is owned by the same user that'll need to write to it later.
