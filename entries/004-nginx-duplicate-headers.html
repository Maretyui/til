nginx doesn't dedupe repeated proxy_set_header in the same block

I was adding a custom location for a websocket endpoint behind a reverse proxy and reused an existing snippet that already sets the usual forwarding headers via an include: 

location /ws {
    include conf.d/include/proxy.conf;
    proxy_set_header Host $host;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
}

The included file already sets Host and the other standard X-Forwarded-* headers. The request started failing with a generic 400, and the backend logs showed a malformed request with a duplicate Host header on the wire.

The cause

proxy_set_header directives don't get deduplicated within the same context just because they share a name — nginx only overrides a directive when a more specific nested context (e.g. a location block overriding its parent server block) redefines it. Two proxy_set_header Host lines in the exact same block both fire, and nginx sends the header twice. Most clients tolerate that for harmless headers, but a duplicated Host header is invalid HTTP and gets rejected outright by some backends.

The fix

Only add headers the include doesn't already set. For a websocket location that's just Upgrade and Connection — drop the redundant Host line entirely: 

location /ws {
    include conf.d/include/proxy.conf;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
}
