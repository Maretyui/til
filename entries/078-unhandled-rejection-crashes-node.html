A long-running bot process kept dying with no stack trace in the logs

A small background worker (a queue consumer, the kind of process meant to just run forever under a process manager) would exit every so often with nothing useful in its log file — no exception, no "Error:" line, just the process manager reporting a restart. The actual cause turned out to be a single fetch() call inside a background interval that wasn't wrapped in try/catch and whose returned promise was never awaited or .catch()'d. Every so often the network call failed (a timeout, a flaky DNS lookup) and that rejected promise had nowhere to go.

Why: Node's default behavior for this changed a while back

Older Node versions just printed a deprecation warning for an unhandled promise rejection and kept the process running — easy to miss, but at least harmless in the moment. Since Node 15, the default flips the other way: an unhandled rejection terminates the process with a non-zero exit code, the same way an uncaught synchronous exception would. That's arguably the more correct behavior (a swallowed rejection is a real bug, not a warning), but it means any fire-and-forget async call anywhere in a codebase is now a live crash risk if a process manager auto-restarts on exit and nobody notices the pattern. 

// this looks fine and runs fine, right up until fetch() rejects
setInterval(() => {
  fetch('https://example.com/api/ping'); // not awaited, no .catch()
}, 30000);
// on a rejection: process exits, restarts, no trace of why

// either handle it locally:
setInterval(() => {
  fetch('https://example.com/api/ping').catch((err) => {
    console.error('ping failed', err);
  });
}, 30000);

// or at least log it centrally so it's visible before the process
// manager just quietly restarts things:
process.on('unhandledRejection', (reason) => {
  console.error('unhandled rejection', reason);
});

The actual lesson

Every fire-and-forget async call in a long-running process needs either its own .catch() or a deliberate top-level process.on('unhandledRejection', ...) handler — not as a substitute for fixing the real bug, but so a silent restart loop turns into a visible, debuggable log line instead.
