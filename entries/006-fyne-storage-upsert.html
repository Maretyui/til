Fyne's Storage.Save() errors if the file doesn't exist yet

Porting a Go/Fyne desktop app's config persistence to Android, the obvious approach was to keep using os.UserHomeDir() plus a hand-built path like .config/AppName/config.json. On a real device that resolved to /sdcard, which scoped storage blocks apps from writing to directly — first run failed with a generic "Failed to save config" and no useful detail.

The fix was to stop building paths by hand and use Fyne's own cross-platform storage API instead, the same one fyne.Preferences relies on internally: 

func saveConfig(a fyne.App, data []byte) error {
  w, err := a.Storage().Save("config.json")
  if err != nil {
    return err
  }
  defer w.Close()
  _, err = w.Write(data)
  return err
}

The catch

Storage.Save(name) is documented as "save data to the named document" — but on first run, that document doesn't exist yet, and Save() returns storage.ErrNotExists instead of creating it. It's an upsert-sounding name with create-only-if-already-there behavior underneath.

The fix

Fall back to Create(name) whenever Save() reports the file is missing, so the call behaves like a normal upsert on every platform: 

func saveConfig(a fyne.App, data []byte) error {
  w, err := a.Storage().Save("config.json")
  if errors.Is(err, storage.ErrNotExists) {
    w, err = a.Storage().Create("config.json")
  }
  if err != nil {
    return err
  }
  defer w.Close()
  _, err = w.Write(data)
  return err
}

Desktop and Windows kept their existing raw-path implementations unchanged (those genuinely worked fine); this storage-API path is gated to the Android build only, since it's the one platform where writing to an app-chosen filesystem path isn't an option at all.
