a client-only boot overlay defaulting to hidden flashes the real page for one frame

Building a splash/boot-sequence overlay for a static-export Next.js site, the obvious-seeming approach was a mounted state starting at false, flipped to true inside a useEffect once the component confirmed it was running in the browser: 

const [visible, setVisible] = useState(false);

useEffect(() => {
  setVisible(true);
}, []);

if (!visible) return null;
return <BootOverlay />;

The assumption was that this overlay would just be the first thing the user sees, since it's the first component to mount. Instead, every page load showed a genuine flash of the real page underneath — nav, hero content, everything — for a single visible frame before the overlay snapped in on top of it.

Why it actually flashes

React requires the server-rendered markup and the very first client render to match exactly, or it warns about a hydration mismatch. Since visible starts false on both the server pass and the first client paint, the overlay genuinely renders null on both — there's no mismatch, but there's also nothing hiding the page behind it yet. Only after that first paint does the useEffect fire, flip the state, and trigger a re-render that finally shows the overlay. Everything in between — server HTML, hydration, first paint — has the real page fully visible.

The fix

Invert the default so the overlay is visible from the start instead of hidden — server render and first client paint then both show the overlay, so there's still no mismatch, just nothing ever flashes. Any browser-only check that might need to skip the overlay (e.g. "already seen this session" via sessionStorage) has to run in useLayoutEffect instead of useEffect, since that's the one that fires synchronously after the DOM is updated but before the browser actually paints — the "hide it" decision lands before the user ever sees a frame, in either direction: 

const useIsomorphicLayoutEffect =
  typeof window !== "undefined" ? useLayoutEffect : useEffect;

const [visible, setVisible] = useState(true);

useIsomorphicLayoutEffect(() => {
  if (sessionStorage.getItem("seenBoot")) {
    setVisible(false);
  } else {
    sessionStorage.setItem("seenBoot", "1");
  }
}, []);

The isomorphic guard matters too — plain useLayoutEffect on the server throws React's "useLayoutEffect does nothing on the server" warning, so it needs the typeof window check to fall back to useEffect during SSR without changing behavior in the browser.
