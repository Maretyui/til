A log embed rejected a message that looked well under any reasonable limit

A bot's audit-log embed dumped a long moderation reason into a single embed field's value, well under a few thousand characters — nowhere near what felt like "a lot of text" for a chat app. The request still got rejected outright with a 400 and a validation error pointing at that one field, not the embed as a whole.

Why: Discord embeds cap each piece separately, not just the total

It's easy to assume there's one overall length budget for an embed, but Discord actually enforces a limit on almost every individual text value inside it, on top of a combined total: 

title            256 characters
description      4096 characters
field.name        256 characters
field.value      1024 characters   ← the one that bit here
footer.text      2048 characters
author.name       256 characters
fields (count)   max 25 per embed
all text combined, across every field above:   6000 characters

A field value tops out at 1024 characters even though the embed's own combined budget is six thousand — so a value that individually clears the smaller cap can still trip the request up long before the embed as a whole gets anywhere near full.

The actual lesson

Truncate (or wrap into multiple fields/a paragraph in the description instead) against the specific field's own limit, not against a single mental "embeds can hold ~6000 characters" number — the smallest applicable cap is the one that actually decides whether the request succeeds. 

const value = reason.length > 1024
  ? reason.slice(0, 1021) + '...'
  : reason;
