Registering a slash command's 26th choice failed command deployment entirely

A bot command let players pick a map from a growing list using a string option with hard-coded .addChoices(...) entries. Adding the 26th map to the list made the whole command registration call reject with a generic validation error on the options array — not just the new choice, the entire command failed to deploy, leaving the previous version live until the extra choice was noticed and removed again.

Why: 25 choices per option is a hard Discord API limit

Discord's application command schema caps choices on a single option at 25 entries, full stop — there's no pagination or "show more" for static choices, and the API returns a validation error for the whole command body rather than truncating the list for you. It's easy to not notice this limit exists until a list that started small (game modes, regions, roles) organically grows past it. 

// fine at registration time, then silently becomes a landmine:
.addStringOption(option =>
  option.setName('map')
    .setDescription('Pick a map')
    .setRequired(true)
    .addChoices(
      { name: 'Dust', value: 'dust' },
      { name: 'Forest', value: 'forest' },
      // ...23 more...
      { name: 'Volcano', value: 'volcano' } // #26 -> whole command rejected
    )
)

The fix that actually scales is dropping static choices for that option and switching to autocomplete instead — setAutocomplete(true) plus an interactionCreate handler that filters the full list server-side based on what the user has typed so far, and returns at most 25 matching suggestions per keystroke. That same 25-item cap applies to autocomplete responses too, but it's a per-request slice of an arbitrarily large list rather than a hard ceiling on how many options can ever exist.

The actual lesson

Any list backing a slash command's static choices is a ticking limit, not just a convenience — if it can plausibly grow (maps, categories, tags, anything admin-editable), build it as autocomplete from day one instead of waiting for the 26th entry to take the whole command down at the next deploy.
