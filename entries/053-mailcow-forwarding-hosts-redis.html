Mail to a list arrived fine, but nobody on the list ever got a copy

A self-hosted mailing list (Mailman sitting behind a Mailcow/Postfix install) accepted incoming mail to the list address without any error — Postfix logs showed a clean status=sent handoff to the list manager container. But the redistributed copies the list manager then tried to send back out to every subscriber never arrived anywhere, with no bounce visible to the original sender either. The failure was completely silent from every angle that would normally surface a delivery problem.

Why: the list manager's own outbound relay looked like spoofing

The redistribution copies go back out through the same Postfix instance, but now with the list's domain in From:/ envelope-from and no SASL auth attached (the list manager is just another container on the internal Docker network, not an authenticated mail client). The spam filter's anti-spoofing composite rule fires on exactly that shape — a locally-hosted domain claimed in the headers without authentication — unless the sending container's IP is explicitly allowlisted as a trusted internal forwarder. It wasn't, so every redistributed message scored well past the reject threshold and was dropped before delivery, with the rejection only visible in the spam filter's own internal log, not anywhere a mail admin would normally look first. 

# the fix: add the list manager container's IP to the forwarding-hosts
# allowlist the spam filter's multimap module reads from
docker exec redis-mailcow-1 redis-cli -a "$REDISPASS" \
  HSET WHITELISTED_FWD_HOST 172.22.1.5/32 mailman-core-list

# no filter restart needed — the map is read live on the next message

The actual lesson

Any internal service that re-sends mail on behalf of a locally hosted domain — list managers, forwarders, relays — needs to be on the mail server's own trusted-forwarder allowlist, or its anti-spoof rules will treat it exactly like an attacker forging that domain. Test with the filter's own symbol-check tool against the real sending IP before assuming "it sent successfully" means "it was delivered."
