A safety rollback timer died silently mid-rollout, along with the SSH session running it

Rolling out a firewall change over SSH included a standard safety net: a backgrounded rollback script armed with a delay, so that if the new rules locked out access the box would revert itself automatically. Partway through verifying the new rules, a cleanup step ran pkill -f rollback.sh to cancel that timer now that the change looked good — and the SSH session running the cleanup step died with it, before the verification/persist step that was supposed to run next ever executed.

Why: -f matches the whole command line, not just the target process

pkill -f PATTERN greps the pattern against each process's full command line, not just its executable name. The command doing the killing was itself invoked over SSH with rollback.sh somewhere in its own argument string (the remote command passed to ssh included the path for logging purposes) — so the pattern matched two processes at once: the actual timer, and the very shell issuing the pkill call. Killing your own shell out from under yourself doesn't error loudly; the connection just drops. 

# looked like it would only ever match the background timer:
pkill -f rollback.sh

# but `ps -ef` at that moment showed both:
#   /bin/bash /root/fw-snapshot/rollback.sh 300      <- the intended target
#   sshd: root@pts/2  bash -c '... rollback.sh ...'  <- the command's own invocation, also matched

The fix

Match on something present in the target process but not in the command issuing the kill — the script's absolute path plus a distinguishing argument, or better, have the rollback script write its own PID to a file on startup and kill by PID instead of by pattern. Also worth re-verifying the actual outcome afterward (config file mtime, persisted rule count) rather than trusting that a command with no error output did what was intended.

The actual lesson

Any pkill -f/pgrep -f pattern is matched against the entire process table's command lines, including whatever shell or wrapper is currently running the match itself — worth a second's thought before running it over the same channel you can't afford to lose.
