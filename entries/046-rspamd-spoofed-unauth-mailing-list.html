List mail arrived at the list server fine, but subscribers never got it

A self-hosted mailing list (Mailman, sitting behind Postfix/Rspamd on the same mail stack as regular inboxes) looked completely healthy from the sender's side — the message reached the list software, logs showed status=sent for the hop into it. No subscriber ever received the redistributed copy, and there was no bounce anywhere for the original sender to notice. It just silently vanished on the way back out.

Why: Rspamd can't tell a legitimate relay from a spoofed From: header

When the list software resends a message, it keeps the original sender's address in From:/envelope-from — which, from Postfix's perspective, is a locally-hosted domain claiming to send mail without SASL authentication. Rspamd's SPOOFED_UNAUTH composite exists exactly to catch real spoofing like that, and it fired on every single redistributed copy, scoring well past the reject threshold with no visible error except a normal-looking reject in the mail log. 

# the fix: allowlist the list server's own container/host IP
# as a trusted forwarding source (Mailcow's "Forwarding Hosts",
# backed by a Redis hash Rspamd's multimap module reads live)
redis-cli HSET WHITELISTED_FWD_HOST 172.22.1.5/32 mailing-list-relay

The actual lesson

Any internal service that resends mail on someone else's behalf — a mailing list, a helpdesk auto-responder, a forwarding rule — needs to be explicitly trusted by the spam filter, or every redistributed copy gets treated as spoofing and disappears with no bounce visible to the original sender. The symptom ("people just don't get list mail sometimes") looks nothing like the cause, so this is worth checking first if a working-looking relay produces zero delivered copies: allowlist the resending service's source IP for forwarding, not just for general sending.
