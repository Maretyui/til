pm2 restart doesn't reload ecosystem.config.js env vars

Changed a DATABASE_URL value in an app's ecosystem.config.js to point at a different host, then ran pm2 restart <name> expecting the process to pick it up. It didn't — every request the app made still went to the old host, for what turned out to be weeks, even though the config file on disk was correct the whole time.

pm2 restart reapplies cached process metadata, not the file

pm2 restart (by name or id) restarts the process using PM2's own in-memory/dumped process metadata — environment variables included — not by re-reading ecosystem.config.js from disk. Even pm2 restart <name> --update-env, which sounds like exactly the right flag, only refreshes env vars from the *current shell*, not from the config file. 

# does NOT re-read ecosystem.config.js:
pm2 restart myapp
pm2 restart myapp --update-env

# actually re-reads it from disk:
pm2 delete myapp
pm2 start ecosystem.config.js
pm2 save

The actual lesson

Any time an ecosystem.config.js env value changes, pm2 delete the process first and start it fresh from the config file, then pm2 save to persist the corrected state — don't trust a plain restart to have noticed the edit, and don't assume a hung/misbehaving request path is a code bug before checking what environment the running process actually has (pm2 env <id> or /proc/<pid>/environ shows the ground truth).
