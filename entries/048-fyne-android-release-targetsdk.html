A freshly built Android APK warned that it was "built for an older version"

Porting a Fyne (Go GUI toolkit) desktop app to Android via fyne-cross produced an installable APK, but Android showed its "this app was built for an older version of Android and may not work properly" warning on install — on a device running a current OS, for an app built the same day. Nothing in the app's own code touched SDK versions at all.

Why: fyne-cross's default build mode hardcodes targetSdkVersion 29

fyne-cross's ordinary (debug) build path is a known, documented gomobile limitation — debug-signed builds pin targetSdkVersion=29 regardless of what SDK is actually installed in the build image, because debug signing on Android has restrictions that release signing doesn't. The app itself was fine; the manifest it shipped with just claimed a years-old target API level, which is exactly the condition that warning exists to catch. 

# the fix: build in release mode, which targets the SDK
# actually available in the build image (35 in this case) —
# but this requires a real keystore, not gomobile's throwaway
# debug-signing identity
fyne-cross android -release \
  -app-id com.example.app \
  -keystore ./release.keystore \
  -keystore-pass "$STOREPASS" \
  -key-password "$KEYPASS"

The actual lesson

A build-time warning that looks like it's about the target device ("built for an older version") can just as easily be about the build's own signing mode instead of anything actually wrong with the code. Worth checking whether debug vs. release signing changes the manifest's declared SDK levels before spending time hunting for a compatibility bug that isn't there — release mode also outputs a Play Store .aab bundle rather than a directly installable APK, so a tool like bundletool is needed afterward to get a sideloadable universal APK back out of it.
