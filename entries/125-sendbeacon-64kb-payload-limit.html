Analytics events kept disappearing, only on pages with a lot of tracked state

A page-unload handler collected a batch of queued analytics events into one JSON payload and fired it with navigator.sendBeacon(), exactly as the API is meant to be used — it's designed to survive the page unloading before a normal fetch() would finish. Most of the time it worked. On pages where the user had clicked around a lot before leaving, the batch just never arrived, with nothing logged client-side or server-side to explain why.

Why: the call returns false for an oversized payload instead of throwing

sendBeacon() has a payload ceiling — 64KB on most engines — and when the body is over that limit, the call doesn't throw, doesn't reject, and doesn't queue the request anyway. It just returns false and silently drops the data: 

const ok = navigator.sendBeacon(url, JSON.stringify(bigBatch));
// ok === false once the JSON string crosses ~64KB — nothing is sent,
// and nothing throws unless the return value is actually checked

The bug only showed up on sessions with enough queued events to push the serialized batch over that limit, which is exactly the kind of session most worth capturing accurately.

The actual lesson

sendBeacon()'s return value is not optional to check — it's the only signal that the send was even attempted. Once a payload can grow unbounded (a batch of queued events, not a single fixed-size ping), either cap the batch size before the unload handler ever runs, or check the boolean and fall back to splitting the payload and retrying smaller chunks instead of assuming "fire and forget" means "always delivered."
