A ticket-panel button worked for most tickets, silently did nothing for a few

A bot built its button custom_id by packing several pieces of state into one string — an action name, a ticket ID, and a snapshot of the category/subcategory path the user picked, e.g. claim:a1b2c3d4-...:billing:refund:duplicate-charge. Most clicks worked fine. A handful of tickets with long category names did nothing at all when the button was clicked — no error logged anywhere, no interaction received by the bot.

Why: Discord enforces a 100-character cap on custom_id, client-side

Discord's component schema caps custom_id at 100 characters. For a handful of the longer category paths, the packed string crept past that limit. The bot never saw an error because the truncation/rejection happens in the Discord client before the click is ever turned into an interaction — from the bot's side, the click simply never arrives. It looks exactly like a dead button, not like a validation failure, so there's no payload or log line pointing at the cause. 

// This builds a custom_id that's valid for short categories and silently
// broken for long ones — nothing here warns you when it crosses 100 chars.
const customId = `claim:${ticketId}:${categoryPath.join(':')}`;

The actual lesson

Treat custom_id as a cramped, fixed-size slot, not a convenient place to serialize state. Store the real state server-side (a ticket/category lookup keyed by ID) and keep the custom_id itself to a short, fixed-shape identifier — and assert its length at the point you build it, so a future change that makes it longer fails loudly in development instead of quietly eating clicks for only the longest-named cases in production.
