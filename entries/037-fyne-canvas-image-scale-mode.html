Fyne's default canvas.Image scale mode redoes CPU resampling on every repaint

After getting a Fyne desktop app's Android build actually installable, the first real device test showed a noticeably sluggish full-screen background image — visible frame stutter just from scrolling content on top of it, on hardware that otherwise ran the rest of the UI fine. The image itself was a static canvas.Image with FillMode: canvas.ImageFillStretch, nothing exotic.

ScaleSmooth is a CPU-side bilinear resample, every single frame

Fyne's canvas.Image defaults to canvas.ImageScaleSmooth, which does bilinear resampling on the CPU and — critically — redoes that resampling on every repaint, not just once when the image is first scaled. On desktop GPUs this is usually cheap enough to not notice. On mobile hardware it shows up immediately as dropped frames, especially for a large full-bleed background image that's present behind every other repaint. 

bg := canvas.NewImageFromResource(wallpaperRes)
bg.FillMode = canvas.ImageFillStretch
bg.ScaleMode = canvas.ImageScaleFastest // GPU-scaled, not resampled per frame

The actual lesson

ImageScaleFastest hands the scaling off to the GPU instead of resampling on the CPU per frame — a strict win for a static background image, since nearest-neighbour vs bilinear is visually indistinguishable at typical stretch ratios but the perf difference is real. Worth setting unconditionally rather than only gating it behind a mobile check: it measurably helped the desktop build too, it just wasn't bad enough there to notice first.
