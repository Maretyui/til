A cleanup job that reported success but never actually ran

A backup-pruning script called an API endpoint with DELETE and a request body carrying the retention rules, exactly the same shape used for the read-only dry-run preview of the same endpoint (a GET with the same body). The response came back 200 with no error. Storage usage afterward hadn't budged at all — and stayed unbudged after several repeat runs, which is what eventually made it obvious that "200 OK" didn't mean what it looked like it meant.

Why: this HTTP client only put params in the body, and DELETE never reads it

Plenty of server frameworks — and the HTTP spec itself leaves this genuinely ambiguous — don't parse a request body on DELETE requests at all, since a body on a delete-by- identifier call is unusual enough that many implementations don't bother. The client library being used sent the same parameter set as either a JSON body or a query string depending on which was passed to it, and for this one call it silently defaulted to body form. The server accepted the connection, found no query parameters to act on, and — instead of rejecting the request — just performed a no-op delete of nothing and returned a normal success code. 

# looked identical, behaved completely differently:
curl -X DELETE 'https://host/api/prune' --data-urlencode 'rules=keep-daily=7'
# -> 200, does nothing, no error surfaced anywhere

curl -X DELETE 'https://host/api/prune?rules=keep-daily=7'
# -> 200, actually prunes

# the safe way to confirm a body-vs-query mismatch: diff the
# GET dry-run's reported actions against what changed afterward,
# don't just trust the DELETE call's own status code

The actual lesson

A 200 response proves the request was received, not that it did what the caller intended — especially for HTTP methods where body support is inconsistent across servers and client libraries. When a destructive/cleanup call's effect can't be directly observed in the response itself, verify against a real before/after state change, not just the absence of an error.
