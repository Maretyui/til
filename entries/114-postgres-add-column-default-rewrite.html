A routine ALTER TABLE on a mid-size table froze every writer for several seconds

Adding a new created_at column to an existing table looked like the safest kind of migration there is — one ALTER TABLE statement, run during a quiet period. Instead it held every other query against that table waiting for a lock for several seconds, long enough to trip a couple of request timeouts elsewhere in the app. 

ALTER TABLE events
  ADD COLUMN created_at timestamptz NOT NULL DEFAULT now();

Why: a volatile default has to be computed per row, which means rewriting the table

Since Postgres 11, adding a column with a constant default (a literal, or anything the planner can prove evaluates to the same value for every row) is a fast, metadata-only change — Postgres just records the default and backfills it lazily on read, without touching existing rows on disk. But now() is volatile: it returns a different value on every call, so Postgres can't use that shortcut. It has to actually compute and write the default into every existing row right away, which means rewriting the entire table and holding an ACCESS EXCLUSIVE lock — blocking all reads and writes on it — for as long as that rewrite takes.

The actual lesson

Any non-constant default (now(), gen_random_uuid(), a sequence via nextval(), anything calling a function) on ADD COLUMN triggers the full rewrite, regardless of table size. The safe pattern is to add the column nullable with no default first, backfill it in batches, then add the NOT NULL constraint (and any default) afterward — each step takes only a brief lock instead of one long one across the whole table: 

ALTER TABLE events ADD COLUMN created_at timestamptz;
-- backfill in batches here, e.g. UPDATE ... WHERE created_at IS NULL LIMIT n
ALTER TABLE events ALTER COLUMN created_at SET DEFAULT now();
ALTER TABLE events ALTER COLUMN created_at SET NOT NULL;

Worth checking the exact default before assuming ADD COLUMN is harmless — a literal default is still the fast path, it's only per-row computed ones that force the rewrite.
