A proxy's server-icon and player-count in the list came from the wrong place

A Velocity-style Minecraft proxy sat in front of several backend servers, each mapped to its own hostname via forced-hosts, so players could type one address and land on the right server automatically. The server list entry for every one of those hostnames showed the proxy's own icon and its own decorative max-player number, never the backend's real ones — even though each backend had a perfectly good icon of its own sitting right there.

Why: ping-passthrough only forwards the MOTD by default

Modern proxies ping the backend on the player's behalf and relay some of that response back to the client, but exactly how much gets relayed is controlled by a single setting, usually something like ping-passthrough. The common default only passes through the MOTD text — description only, not the favicon and not the real player counts — so the proxy quietly falls back to its own values for everything else. Nothing errors, nothing logs a warning; the server list just silently shows proxy-level data dressed up as backend-specific data. 

# proxy config, roughly
[servers]
ping-passthrough = "description"   # MOTD only, icon/counts stay the proxy's own
# ping-passthrough = "all"         # backend's icon + real player count too

The catch with switching it to "all"

Passing everything through means the backend's own max-players value is now what players see, not any decorative placeholder number configured on the proxy. If a backend was relying on the proxy's fake high player-count for cosmetic reasons, that illusion breaks the moment passthrough is widened — the fix for one problem (missing icon) exposes a value (real player cap) that was previously hidden on purpose. Worth deciding on both before flipping the setting, not just the one that prompted the change.
