Docker's iptables rules bypass ufw port filtering entirely

Set up a container with docker run -p 8085:80 ... and wanted it reachable only from one internal network, not the whole LAN. The instinctive fix was the usual one for any other service on the host: 

ufw deny in on eth0 to any port 8085

That rule looked correct in ufw status, and it works perfectly for anything ufw actually mediates. It did nothing here — the container stayed reachable from the LAN interface regardless.

Docker manages its own iptables chains, ahead of ufw's

Docker's default networking inserts its own DOCKER and DOCKER-USER chains directly into iptables and wires published ports through DNAT rules in the nat table. Those rules get evaluated before ufw's own chain gets a say — from iptables' point of view, Docker's port-forwarding rule matches first and the packet is accepted and forwarded straight into the container's network namespace, so ufw's deny rule for that port never actually gets consulted. This isn't a bug in ufw; it's just two independent iptables rule-management systems that don't know about each other, and Docker's happens to run first.

The fix: don't publish to a wildcard port at all

Rather than fight Docker's chain ordering (editing DOCKER-USER directly is possible but easy to lose on the next Docker upgrade), bind the published port to a single specific interface IP instead of the default 0.0.0.0: 

docker run -p 100.64.0.5:8085:80 ...

With an explicit bind address, the container is only reachable via that one interface — no DNAT rule ever gets created for any other interface, so there's nothing for a ufw rule to have needed to block in the first place. Verified: reachable over that specific IP, connection-refused on every other interface's address.

The actual lesson

A ufw rule that looks right and shows up correctly in ufw status can still be silently ineffective against Docker-published ports. For anything running in Docker, prefer an explicit bind-address in the -p mapping over trying to firewall the port after the fact.
