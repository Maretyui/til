A Discord interaction token is only valid for 15 minutes, deferring or not

A ticket-bot button handler that did a slow chain of work — a permission check, a database write, then a channel rename — started throwing DiscordAPIError[10062]: Unknown interaction on tickets that had been open for a while, even though the exact same handler worked fine on a fresh ticket seconds after creation.

The assumption that turned out wrong

The instinct was that interaction.deferReply() "resets the clock" — that once you acknowledge an interaction, you have a fresh window to do slow work before replying. That's not what it does. Deferring only satisfies Discord's initial 3-second ack requirement so the "thinking..." state shows up instead of a failed interaction. It doesn't extend anything.

The interaction token itself — the thing editReply()/followUp() actually authenticate with — is unconditionally valid for 15 minutes from the moment the user triggered the interaction, full stop. Defer or don't defer, that window is fixed. If any part of the handler (an awaited DB query, an external HTTP call, a rate-limited Discord API call like a channel rename) is slow enough that the token's 15-minute lifetime has already elapsed by the time editReply() runs, the edit fails with the same generic "Unknown interaction" error — no matter how early the defer happened.

Why it only showed up on older tickets

// simplified shape of the actual bug
async function onClaimButton(interaction) {
  await interaction.deferReply();       // ack within 3s, fine
  await slowDbLookup(ticket.id);         // fast normally
  await channel.setName(newName);        // can silently queue behind
                                          // Discord's 2-per-10-min
                                          // channel rename rate limit
  await interaction.editReply("Claimed"); // token may already be dead
}

Channels that had already been renamed recently (claim, then unclaim, then reclaim) queued the next rename behind Discord's rate limit for that specific action. On a quiet ticket that wait was invisible; on a busy one it was long enough to blow straight past the interaction token's 15-minute ceiling, and the final editReply() failed.

The actual lesson

Treat 15 minutes as a hard, unconditional deadline for any given interaction, not a budget that deferring resets. If a handler does anything that can be rate-limited or genuinely slow (renames, external calls, retries), either keep it well under that ceiling or restructure the flow so the user-visible reply happens fast and the slow work continues afterward as its own follow-up action, rather than gating the reply on it.
